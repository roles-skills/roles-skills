# Change and release manager

> This is an illustrative reference profile for a generic digital health care organisation. It is not an official job description for any employer, and its job evaluation scores are not a formal evaluation.

**Family:** [IT operations](../../#it-operations)  
**Bands:** 4, 5, 6  
**UK GDaD PCF role:** [Change and release manager](https://understand-digital-data-roles-skills.service.gov.uk/role/change-and-release-manager/)  
**ESCO occupations:** [ICT change and configuration manager](http://data.europa.eu/esco/occupation/3b1ea27c-781c-41eb-821f-214285260dd2) (ISCO-08 2519)

## Summary

Change and release managers make sure changes to IT services are assessed, approved, scheduled, and carried out safely, and that releases are planned and coordinated. They run the change advisory board, own the configuration management database, and coordinate releases across teams and suppliers. In health care, they make sure changes to clinical systems are timed and tested to protect patient care.

## In a digital health care organisation

- Changes to clinical systems can harm patients, so change assessment includes clinical safety review and evidence from the clinical risk management process.
- Clinical services run every day, so change windows are agreed with clinical services and avoid their busiest periods.
- Many changes come from suppliers of clinical systems, and must still be assessed when the supplier controls the release.
- Emergency changes, such as urgent security patches, must balance cyber risk against the risk of disrupting care.
- An accurate configuration management database shows which clinical services a change could affect.

## UK GDaD PCF role description

> Change and release managers lead the change advisory board, ensuring adequate risk assessment and scheduling of technical changes and releases. They own the configuration management database and the access, security and configuration of change activities and release procedures.

## Band 4: Configuration analyst

**UK GDaD PCF level: Configuration analyst**

> A configuration analyst provides administrative support to the change and release manager, helping to maintain the integrity of the configuration management database (CMDB) and independently solving smaller problems.

### Responsibilities

- Maintain records in the configuration management database, including the clinical services each component supports.
- Check configuration records against discovery tools, and fix gaps and errors.
- Prepare change records and agendas for the change advisory board.
- Answer routine queries about configuration items and how they relate.

## Band 5: Change and release analyst

**UK GDaD PCF level: Change and release analyst**

> A change and release analyst plans and rolls out software, and designs and carries out procedures for the distribution and installation of changes to systems and services.
> 
> At this role level, you will:
> - undertake analysis after release and set the plan for upcoming changes
> - liaise with DevOps and service designers

### Responsibilities

- Assess change requests for risk and impact, including the effect on clinical services and patient safety.
- Plan and schedule releases, agreeing change windows with clinical and operational services.
- Check that each change has testing, a rollback plan, and clinical safety sign-off where needed.
- Coordinate releases with DevOps teams, suppliers, and the service desk.
- Review releases afterwards and plan upcoming changes.

## Band 6: Change and release manager

**UK GDaD PCF level: Change and release manager**

> A change and release manager ensures that technical changes to IT services are adequately assessed for impact, prioritised, scheduled, authorised and implemented. They ensure this is done in line with processes and using appropriate tools. They chair the Change Advisory Board (CAB).
> 
> At this role level, you will:
> - provide an escalation point
> - make decisions for all technical changes
> - co-ordinate releases and interdependencies

### Responsibilities

- Chair the change advisory board, including clinical and operational representatives when changes affect patient care.
- Decide on technical changes, and authorise emergency changes such as urgent security patches.
- Coordinate releases and their dependencies across in-house teams and suppliers.
- Own the change, release, and configuration management processes and the configuration management database.
- Act as the escalation point for change conflicts and failed changes.
- Report on change success, failed changes, and incidents caused by change, and drive improvements.
