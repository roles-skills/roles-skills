# 安全工程师

> 这是一份面向通用数字医疗卫生机构的示例性参考档案。它不是任何雇主的正式职位说明，其中的岗位评估分数也不是正式评估。

**UK GDaD PCF 角色:** 无（本参考资料定义该角色）

## 概述

安全工程师设计、构建和运行保护组织系统、数据和用户的技术安全控制措施。他们从事身份与访问、终端和网络防护、加密、日志和云安全方面的工作，并帮助产品和基础设施团队将安全内置其中。在医疗卫生领域，他们在保护临床系统和患者数据的同时，保持临床医生在照护现场的快速访问。

## 在数字医疗卫生机构中

- 安全控制措施不得妨碍紧急照护，因此工程师设计在共享临床工作站上仍能快速使用的强身份验证。
- 医疗器械和遗留临床系统往往无法打补丁或运行安全软件，因此工程师设计网络分段和补偿性控制措施。
- 勒索软件是医疗卫生面临的重大威胁，因此工程师加固系统、保护备份，并限制攻击的扩散范围。
- 临床系统通常由第三方提供和支持，因此工程师评估供应商的安全性并控制其远程访问。
- 对临床系统安全控制措施的变更要经过变更管理，必要时还要经过临床安全审查。

## 职级 6: 安全工程师

安全工程师构建、配置和维护安全控制措施和工具，并帮助团队修复安全弱点。

### 职责

- 构建和维护终端防护、防火墙、电子邮件安全和安全日志等安全控制措施。
- 配置身份与访问控制，包括多因素身份验证和特权访问。
- 帮助基础设施和产品团队修复漏洞，并按商定标准加固系统。
- 与基础设施和临床工程团队合作，对网络进行分段以保护医疗器械和遗留系统。
- 在新系统和供应商远程访问上线前审查其安全性。
- 参加值班轮换，支持安全事件响应。

### 典型资质与经验

- 计算机或网络安全学位、相关安全认证，或同等经验。
- 具有构建或运行基础设施或安全工具的经验。

### 职级概要

- **知识:** 通过进一步培训或经验积累，具备覆盖一系列流程的专门知识。
- **自主性:** 独立工作；为本领域解读政策；在复杂问题上寻求建议。
- **范围:** 一个产品、服务或工作流。
- **领导力:** 可能领导一个小团队或指导同事。
- **问责:** 自己工作流的成果以及所提供建议的质量。

## 职级 7: 高级安全工程师

高级安全工程师设计并领导交付重要的安全控制措施，并就安全设计向团队提供建议。

### 职责

- 设计并领导交付特权访问管理、安全监控和备份保护等安全控制措施。
- 就临床服务和面向患者服务的安全设计向产品和基础设施团队提供建议。
- 为医疗器械和其他无法打补丁的系统设计补偿性控制措施。
- 评估供应商及其产品（包括云服务）的安全性。
- 以技术专长和恢复计划支持对严重安全事件的响应。
- 辅导安全工程师，并在各团队之间分享良好实践。

## 职级 8a: 首席安全工程师

首席安全工程师确定安全工程的技术方向，并确保全组织的各项控制措施协同运作。

### 职责

- 为全组织的安全控制措施确定技术方向和标准。
- 领导重大项目群的安全设计，例如迁移到云托管或新的电子病历系统。
- 确保控制措施能够防范勒索软件，并支持快速、安全地恢复临床系统。
- 与临床负责人一起在访问和身份验证方面平衡安全与临床可用性。
- 就技术风险和投资向网络安全经理提供建议。
- 领导和培养安全工程师。
