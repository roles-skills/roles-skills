## 概要

変更・リリースマネージャーは、IT サービスへの変更が、評価され、承認され、スケジュールされ、安全に実施されるようにし、リリースが計画されて調整されるようにする。変更諮問委員会を運営し、構成管理データベースを担い、チームと供給者にまたがるリリースを調整する。医療では、臨床システムへの変更が、患者のケアを守るようにタイミングとテストが計られるようにする。

## デジタルヘルスケア組織において

- 臨床システムへの変更は患者に害を及ぼしうるため、変更の評価には、臨床安全レビューと、臨床リスク管理プロセスの根拠が含まれる。
- 臨床サービスは毎日稼働しているため、変更の時間枠は臨床サービスと合意され、最も忙しい時間帯を避ける。
- 多くの変更は臨床システムの供給者から来るため、供給者がリリースを管理している場合でも、評価しなければならない。
- 緊急のセキュリティパッチなどの緊急変更では、サイバーリスクと、ケアを妨げるリスクのバランスをとらなければならない。
- 正確な構成管理データベースは、変更がどの臨床サービスに影響しうるかを示す。

- 事後にリリースをレビューし、今後の変更を計画する。

## バンド 6: 変更・リリースマネージャー

**UK GDaD PCF のレベル: Change and release manager**

> A change and release manager ensures that technical changes to IT services are adequately assessed for impact, prioritised, scheduled, authorised and implemented. They ensure this is done in line with processes and using appropriate tools. They chair the Change Advisory Board (CAB).
> 
> At this role level, you will:
> - provide an escalation point
> - make decisions for all technical changes
> - co-ordinate releases and interdependencies

### 責任

- 変更が患者のケアに影響する場合は臨床・運用の代表者を交えて、変更諮問委員会を主宰する。
- 技術的な変更を判断し、緊急のセキュリティパッチなどの緊急変更を承認する。
- 社内チームと供給者にまたがって、リリースとその依存関係を調整する。
- 変更、リリース、構成管理のプロセスと構成管理データベースを担う。
- 変更の衝突や失敗した変更のエスカレーション先を務める。
- 変更の成功、失敗した変更、変更が原因のインシデントを報告し、改善を推進する。

- **リーダーシップ:** 小さなチームを率いたり、同僚をメンターしたりすることがある。
- **説明責任:** 自分のワークストリームの成果と、提供した助言の質。
